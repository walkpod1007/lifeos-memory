# 六大失敗模式檢查表 — skill 寫作與改版自查

> 源：Matt Pocock `skills/productivity/writing-great-skills`（github.com/mattpocock/skills，
> path commit `697d4ce9742d` 2026-07-13，抓取時 head `ed37663cc5fb` 2026-07-21；抓取日 2026-07-24）。
> 用法：造新 skill 或改版舊 skill 時，六條逐一過，每條問「這份 SKILL.md 有沒有犯」；
> 命中就修，修不動的記成待辦事項。上位原則：skill 存在是為了從隨機系統裡擰出可預測性——
> 每次跑同樣的**流程**，不是同樣的輸出。六條全是「可預測性」的敵人。
> 正反例皆為 **as-of 2026-07-24 的歷史案例**：佐證機制用，不代表引用對象的現況
> （行數、殘留與否都會變）；例子過時不影響六條定義本身。

## 過早完成

步驟還沒真做完，注意力已經滑向「做完了」。根源多半是完成判準含糊——寫「產出變更清單」
（做到什麼程度算完？）而不是「每個改過的 model 都有對應項」（可逐一核對）。
修法順序：先把完成判準磨利（便宜、局部），真的磨不利再把後續步驟拆出視線外。

- 反例（案例）：某個保留資料的機制把「程式改完」當作「修好」，空轉 84 天才發現（某份內部作業規範第 6 步引案）。
- 正例（案例）：某個收尾腳本做到三件一體——工作項狀態翻成已完成＋看板上的卡片消失＋收尾紀錄落行，
  缺一即非零退出，「收工」是可機檢狀態不是感覺（同一份內部作業規範第 8 步）。

## 重複建設

同一個意思活在兩個地方。付雙倍維護費與 token 費，還讓那個意思在階梯上的地位虛胖；
兩處各自演化後必然漂移打架。修法：收斂成單一權威源，其他位置只放指標。

- 反例（案例）：某個草稿技能內含一個「先被追問一輪」的前置段，與既有的追問原語
  實質重複且規則互撞——一次問 3–5 題 vs 一次只問一題（2026-07-24 開案時紅隊實抓）。
- 正例（案例）：某份作業規範第 5 步的派工必填清單寫「以模型派工規範 §2 為唯一權威版，
  本步不另列舉，免得兩處各自演化漂移」。

## 沉積

過時層積著不清，因為「加上去」感覺安全、「拿掉」感覺危險。沒有修剪紀律的 skill 的預設命運。
修法：把「刪」制度化——廢棄表、archive 目錄、定期 relevance 掃描，讓每行都答得出
「還跟這個 skill 現在做的事有關嗎」。

- 反例（案例）：某個技能在 2026-07-03 被移進資源回收區，路由表上的對應路由行掛了三週
  沒人清（2026-07-24 本次清理才清）；某份白名單當時仍殘留兩個已廢棄的舊通道設定。
- 正例（案例）：把「廢棄項目表」寫成中央索引的慣例——
  廢一個就登記一筆，「不要復活、不要當異常報」寫成中央索引。

## 蔓生

就算每行都活著、都不重複，整份還是太長。傷可讀性、傷維護、燒 token。
修法是資訊階梯：步驟留頂層，reference 推下去（獨立檔＋context pointer），
分支各自載自己需要的料——每條路徑只背自己的行李。

- 反例（案例）：某個技能的 SKILL.md 有 879 行、15 處「例外」，單檔背了所有平台分支的細節。
- 正例（案例）：skill-author 出生義務「正文 ≤80 行」＋本檔自己——failure-modes 內容
  從 SKILL.md 推到 references/ 一層，SKILL.md 只留一行指標。

## no-op 廢話

模型預設就會做的事，你花 token 再說一遍——付了載重、改變了零行為。
逐句測：「這句拿掉，行為會變嗎？」不變就整句刪，不是修短。
弱領頭詞也是 no-op（模型本來就大致 thorough，寫 be thorough 沒用；要換更強的詞，不是換技巧）。

- 反例（案例）：某個技能舊版「禁自動抓」條款配六處例外——例外清單把禁令架空，
  規則存在但不改變任何行為，形同整段 no-op（2026-07 稽核，後改絕對禁止設計）。
- 正例（案例）：把禁語清單寫進權威的坑卡投影檔（由規則投影步驟自動生成，權威源＝固化後的坑卡）
  裡（「不急」「有空再看」…）過得了 no-op 測試——
  模型預設真的會說這些話，列出來就是改變行為。

## 否定式框架

用禁止來導航會反噬：「不要想大象」先把大象叫上台。修法：陳述目標行為，讓被禁的說法
根本不出場；真的只能用禁令的硬紅線，附上「改做什麼」。

- 反例（源文原理示例）：整份 skill 用「don't / 禁止」堆出來，模型滿腦子都是被禁的那件事。
- 正例（案例）：坑卡「回應直入內容：每段回應第一句直接接內容本身——具體反應、
  判斷、追問、延伸或行動」（見同上投影檔）——先立正向目標，禁語清單只當硬 guardrail 殿後。

## 補充：leading words（領頭詞）

領頭詞＝模型預訓練裡現成的緊湊概念，執行時拿來「用它思考」，一個詞錨定一整片行為。
改版時主動找「三個地方各講一遍的三合一」「一句話繞著講一個概念」——都是等著塌縮成
單一領頭詞的段落。塌縮贏兩次：省 token＋給模型更利的思考鉤子。

## 補充：完成判準（completion criterion）

每個步驟以完成判準收尾，判準要「可核對」（做完/沒做完分得出來）且必要處「窮盡式」
（「每個改過的 X 都有對應項」而非「產出清單」）。落地形態＝驗收條件
可機檢鐵則（命令＋預期輸出，寫不出就回頭重拆）——含糊判準正是「過早完成」的邀請函。
